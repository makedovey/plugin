# The tools this plugin's skills name

Generated by api/scripts/build_plugin_skill.py from the tools' own descriptions (api/core, the registry the MCP server lists). The full list is what your host shows for the `klayson` server.

## add_frame

Add a frame to a workflow: type asset, reference, research, brief, output, text, shots (Product shots, with the designed ads), template or brand (a template canvas), with its data. With after set to a frame id it is placed to the right of that frame and connected to it; without, to the right of everything. Build in order asset → research → brief → output, passing after each time. A new frame starts stale (not run yet).

## add_frames

Add frames: n empty ads (a blank document in the brand's tokens, to design with write_html) or, with template_ids, the canvas's own editable copies of those library templates (list_library_templates), one frame each. size 4:5 (default), 1:1 or 9:16. Two or more go into a new group (group_title) unless group_id names one. titles names them in order (a carousel's slides: titles=["Slide 1 hook", "Slide 2 proof"], n then defaults to how many titles there are); a blank frame without one is named Frame 1, Frame 2, … with a number no item on the canvas has. Returns frames (the new item ids) and design_ids ({item id: dsg_…}, the ads write_html and the frame tools take). Free, no model; making ads for the brand is make_frames.

## batch_edit

Many edits to one ad in one call, applied in order, all or nothing: one save, one version, one undo step, one receipt. ops is a list of {tool, args}: tool one of the canvas's edits (the enum), args that tool's own arguments (design_id is this one). An op that fails stores nothing and the answer says which op and why. Example: batch_edit(design_id, rev, ops=[{tool: "set_text", args: {updates: [{node_id: "n5", text: "Calm energy"}]}}, {tool: "update_styles", args: {updates: [{node_ids: ["n5"], styles: {fontSize: "96px"}}]}}, {tool: "move_nodes", args: {moves: [{node_id: "logo", after: "cta"}]}}]). Free.

## confirm_product_cutout

The person confirmed that a product's cutout is their product and looks right: stored on the cutout with who and when. Only after the person said so.

## create_canvas

Start a new canvas (a project with one page). With no seed it is empty, named "Untitled canvas" unless a name is given: build it with add_frame on its workflow_id. With reference_ad_id (an ad id from search_ads) it is the Remix canvas, named "{brand} remix": Reference (that ad) → Asset (empty) → Output (3 ads), connected. Its Run waits for the product photo: update_frame on the Asset with an asset_id (upload_asset or the brand's products), or asset_ids for several photos (each ad uses the next one), then run_workflow when the person says go. Free; nothing runs.

## create_frame

Start a canvas frame: an ad laid out as HTML and CSS (flexbox), the way a design tool lays out a frame. Pass a size (feed, square, story) or w and h, a name, and the page (a canvas is a page: its canvas id or its name; canvas_id is read as page and title as name). The frame comes back empty and white with the brand's tokens (--color-primary, --color-ink, --font-display, --font-body …) set on it; write_html fills it.

## create_upload_link

Get a link that puts images straight into this workspace, for a file attached in chat or on the person's computer (a chat attachment cannot be passed as an argument). If you can run a shell or code and the file is on disk (a path you were given, an upload folder), send it yourself: run upload_command with the file's path; the answer is the asset. Otherwise give the person the upload_url to click and drop their images on. Either way each image lands as an asset (asset_id for add_image, make_frames, set_product_photo; list_assets shows them). The link works for an hour, as many times as needed, and only adds images to this workspace. kind defaults to product (screen for an app or website screenshot). kind file takes a document instead: the brand's own brand guide as a PDF, Word (.docx), PowerPoint (.pptx), text or markdown file, up to 50 MB; its asset_id is what import_brand_guide takes. A Google Docs or Google Slides guide needs no link: pass its share link as url to import_brand_guide. kind library takes what the brand's library keeps: a picture, a GIF, an MP4 or WebM video up to 50 MB, or a Lottie JSON.

## find_templates

Reference layouts from Klayson's library that fit what the person asked for, matched on their words: the angle (an offer, a comparison, reviews, how it works, native or UGC, the product, a launch), the occasion (Black Friday, Cyber Monday, the holidays, the new year), the look (a text message, a Notes list, a search bar, minimal, luxury, dark) and the brand (what it sells, whether it has a rating, an offer, several products). A template is a reference to adapt, never what makes the ad: every ad is drawn by hand for the brand. Returns the best few (limit, default 6), never two of one look, each with id, title, url (its picture), why (what in the ask it matched), fit (0 to 1) and tailor (what to change for this ask); read says how the ask was understood. weak true when nothing fits well: draw from the brand's own ads alone. kit narrows to kits; type to one type of ad (evergreen, bottom_of_funnel, top_of_funnel, social_proof, comparison, product_benefits, native_ugc, seasonal). Free. To use one: get_library_template reads its layout and you redraw it by hand for the brand (get_canvas_guide, get_brand_pieces, add_frames, write_html), or make_frames with template_ids has Klayson redraw each by hand. Nothing of a template's sample brand stays on the ad.

## get_brand_pieces

The brand's own pieces: its running ads and social posts, as pictures, its running ads first (the longest running first), then its posts. Look at four to six before designing anything for the brand: they show how it composes its own work (the tokens say what colors and faces, the pieces say how). Each says its kind (ad or post), its tag (campaign_ad, product_photo, lifestyle, ugc, event) and where it came from. For an ad, the brand's ads are the reference; its posts are often a different series. A piece marked not_a_layout_source is built on someone else's character, film or licensed artwork (a collaboration, a licence line): never follow it. family=character lists the brand's own character or mascot files kept from its site instead (illustration: its drawn pictures): files to place as they are, never to redraw. `characters` says how many there are.

## get_brand_style

The brand's style as its ads use it (onboarding's "This is your brand style"): the headline and label faces, the colors (primary, secondary, accent, background, ink), the button (color, shape, case, arrow), the logo and its light version, what the site read found, whether the site gave little (then three starter styles), the fonts to choose from, whether the person confirmed it, and a sample ad (a canvas document) drawn in it with their product.

## get_canvas_guide

How to draw an ad for this brand on Klayson's canvas, for any agent. It opens with the brand's own pieces (its running ads first, as pictures) and how the brand composes them: look at those before drawing. Then the method (brief first, the brand's own devices redrawn, one look and one question after each, fix in place, never start over), the checklist the lint measures, the HTML contract, type sized as the brand sizes its own, safe zones, the brand rule and the tools. Read it once per session, before the first frame. method=true adds the same steps and checklist as data (the text already has them).

## get_canvas_items

What is on a canvas (the board: frames, groups of frames, text notes, images), as an outline: one line an item with its kind, title, id, box [x,y wxh], a frame's size, design_id and status (done, queued, making, waiting, failed) and how it is shown (a Facebook or Instagram post, else the creative alone), a group's layout and progress. words=true adds every ad's words. Read it before changing a canvas and address items by id; a frame's design_id works with every ad tool (get_frame_tree, update_styles, set_text …). Also the canvas's template (a group, a note and the prompt) and the makes running. if_changed_since=rev answers {unchanged} when nothing moved.

## get_frame_tree

Orient yourself on an ad: its layers as an outline, one line each (kind, name, id, the box it is drawn in as [x,y wxh] in frame pixels, a text's first words, hidden or locked), about 1 to 2k tokens. Read it before editing so you address layers by id; then get_node_info for the few you change. depth (default 6), node_id (one layer's subtree), fields (any of kind, name, text, box, sizes, src, state) narrow it; full=true gives the old tree with the sizes set on every layer and the tokens. if_changed_since=rev answers {unchanged} when nothing moved.

## get_job

Status of a background job: queued | running | done | failed. done carries output, failed carries error. While running, stage is a short human line describing the current step, and progress {done, total} counts finished variants on generate jobs. queue_position appears while queued; estimated_seconds is the typical total duration for this kind of job — poll roughly every estimated_seconds/4. wait true answers once the job is done or failed (up to about 40 seconds; call again with wait true while it still runs), so no polling. A canvas make's output and progress carry design_ids ({frame item id: dsg_…}): the ads to edit next.

## get_library

The brand's library: the work its team approved and the references it keeps, newest first. Before you make something for a medium, call it with that medium (web, app, ads, social, slides, email or print) and match what was approved: its layout, its density, its tone. The brand's own running ads and social posts are in it as approved. Filter by status (approved or reference), medium and kind (image, video, motion, code, page, link). Each card has its title, kind, medium, status, a picture (thumb_url), its address or the start of its code, and a note on why it is good. item_id answers one item in full, its whole code included. A reference is something the team likes that is not its own: take the idea, never copy it.

## get_library_template

One library template with its ad as a canvas document (the layout, the proven ad's words and products): what the Templates page's dialog draws and what a canvas copies into its Template frame. Free.

## get_me

Who am I: user, workspace, brand summary, and this month's usage. Read-only: call it to verify the connection. setup says what the brand setup has recorded (brand: the website was read; product: the main product's cutout confirmed, or a service, an app or a SaaS with no photo to confirm; style: the brand style confirmed, exactly get_brand_style's confirmed; facts: always true, no longer a step) and done: whether it still needs the person. done false: finish the steps in missing with the person before the first ad. done true: the workspace is set up and missing is empty, never walk it through setup again; unconfirmed lists a step never recorded (an unconfirmed style is the one get_brand_style shows in force, and every new frame uses it; once the workspace is set up, every brand's unconfirmed style is listed there, never in missing). pending_template is the Klayson template the person came for (slug, title, url, token) while it has not been made: offer it right after the setup (get_template, use_workflow with its token, then their product photo). In a workspace with several brands, brands lists each with its own setup (done, missing, unconfirmed), and brand names the one whose setup the answer's setup is (left out: the first brand's).

## get_onboarding_product

The onboarding's product step: the brand's main product with its cutout (a transparent PNG of the product, url, grade, whether the edges look rough and the one line to show then), the other photos it could be cut from (candidates) and the brand color it sits on. Whether the person confirmed it is cutout.confirmed. A product with no photo answers state none and needs_photo: false for a service, an app or a SaaS (nothing to confirm, never ask for a photo), true for a physical product (ask for one). next_step says what to do.

## get_plan

A Brief (the table of planned ads plan_creatives writes; never the billing plan) with its rows, each row's creative (render_url, ad copy) once made, and the person's verdicts.

## get_workflow

A workflow: the document (frames, edges, notes) plus, under hydrated by frame id, what every frame points at: the research ads with their pictures, the brief's rows, the output's creatives (render_url, ad copy, run), the asset's picture. Also which frames are stale (out of date) and what running them would cost. Read this before editing a page.

## list_canvases

The workspace's canvases. Each canvas is one project with one page: a workflow of frames (Reference, Asset, Research, Brief, Output) from research to finished ads. Each with its name, when it was last edited, how many ads it holds (or Draft), its workflow_id for the workflow tools (get_workflow, add_frame, run_workflow), and a picture of its flow. q filters by name; sort is edited (default), name or created.

## list_library_templates

The Templates page's ads: every library template (a proven ad rebuilt as a Klayson layout, shown as a finished example), with its picture, its layout and whether this workspace bookmarked it. q searches the library's metadata (format, angle, goal, occasion, offer, tone, product type) and each template's words. Founders with admin true also see the templates not approved, with their status. kit narrows to the templates of one or more kits (each template lists its kits): with no creative direction from the person, pick the ads from the kits that fit their goal, varied across them. limit and offset page through them (an assistant gets 40 at a time unless it asks; total says how many match, next_offset where the next page starts). Example: list_library_templates(kit="bfcm,offer", limit=20). type narrows to one type of ad (evergreen, bottom_of_funnel, top_of_funnel, social_proof, comparison, product_benefits, native_ugc, seasonal; each template lists its types, type_counts says how many of the matches sit in each). Free. create_canvas_from_templates makes a canvas from any of them.

## make_ad_size

For any change the person asks to an ad Klayson made or showed in this conversation, even when they don't say Klayson. The ad in another size, kept linked, like the 4:5 / 1:1 / 9:16 tabs on a selected ad: a sibling version of its own (fully editable with every canvas tool), put on the ad's canvas as a frame beside it (the answer's item_id; make_sizes does several frames or a whole group at once). size is 4:5 (feed), 1:1 (square) or 9:16 (story). A layout ad is laid out again for the size by the engine with your edits carried over; any other ad (a template's copy, a free-layout ad) is fitted to the size's safe area, nothing cut or stretched. Words you change on the original follow to each size until that size is edited itself. Asking again for a size that exists returns it (idempotent); called on a size, it works from its original. Example: make_ad_size(design_id, size="9:16"). Returns the new design_id. Free, no picture made.

## make_design

Have Klayson design one ad from words, in the brand: Klayson's designer draws it by hand from the brand's own running ads, with the brand's product, logo, colors, type and words, every layer editable (headline, body, button, product, logo), plus the primary text and headline to publish it with. No template is filled in and no image model is used. Pass prompt (the brief in the person's words), product (one of the brand's products by name) and photo_url (a photo of their product they uploaded) when given. For several variations call it once per variation, each with its own brief (a different angle and headline direction), in the same step. Drawing takes a few minutes: the design comes back with its render_url, or, when it is still being drawn, with status drawing and a job_id (get_job with wait true says when it is done; do not make it again). Change it afterwards with the layer tools (get_frame_tree, then set_text, replace_text, update_styles or batch_edit).

## make_frames

Have Klayson design ads on the canvas for the brand: a new group of n frames (one loose frame when n is 1), every frame titled at once and filled in as each ad lands. Klayson's designer draws each ad by hand from the brand's own running ads (its palette and proportions, its type, its devices, how much type it sets on a picture and how large), with the brand's real product or its own clean photographs, three at a time, a few minutes an ad. In a batch about seven ads in ten follow one of the brand's own ad layouts and three are new layouts built from its parts. There is no template engine, no image model and no picture mode. With plan_id (the Brief you wrote: get_creative_direction, then plan_creatives with your rows) its rows are the ads, each row's headline exactly as written, and any row still in write_copy has its words settled in code (copy_settled_in_code); without a plan_id Klayson writes the Brief and the copy itself, for when no agent is writing them. A short line, a button and a price go on the picture only when the brand's own ads carry that much type; otherwise they run with the ad (its ad_copy). from_item remakes the idea of an image on the canvas (a competitor's ad or an uploaded ad) n times for the brand. template_ids (find_templates or list_library_templates) are reference layouts: Klayson redraws each by hand for the brand, one frame each, in a group titled group_title. group_id makes the frames a make left waiting (the month's usage ran out) or failed. When an ad's answer says it needs a clean photograph, ask the person to upload one and make it again with its asset_id. Use make_frames when the person wants Klayson to design the ads; an assistant that can design draws them itself (get_canvas_guide, get_brand_pieces, add_frames, write_html). Runs at once; what the balance does not cover waits. Returns the group and the job.

## make_plan

Make a Brief's ads (a Brief is the table of planned ads plan_creatives writes): every row becomes a creative in the brand's colors and type, on the Brief's page, three at a time. Returns at once with a job; the card fills in as they land, or poll get_plan. Pass rows to make only some (their n).

## meta_ad_results

Where these ads stand on Meta (publishing, paused, active, rejected, couldn't publish) and, for ads on Meta, the last 7 days from Meta: spend, impressions, clicks, CTR and cost per result. Read from Meta at most once an hour per ad.

## meta_publish_prepare

Prepare publishing ads to the connected Meta ad account, for the person to confirm. Use this when the person says go, publish or put these live: it never publishes. It returns the settings in plain words (account, objective, daily budget, audience, placements, each ad) and a confirmation the person presses: a card with a Publish button where the assistant shows cards, else confirm_url to open in Klayson. Tell the person what will happen and that they press Publish. go_live=true (the default) is Publish: live at once, spending at the shown budget once they press it; false is Draft: the ads are created paused and spend nothing until the person presses Publish on them.

## plan_creatives

The Brief before a batch: a table of N ads for this brand, every row different in angle, visual or hook, each with the ad it borrows from and what it tests. You write it: get_creative_direction first, then this with its direction_id, your rows, title and summary; Klayson keeps your words, chooses each ad's layout variant, ground and cutout, checks the copy and sends back in write_copy any row to write again. Without rows Klayson writes the Brief itself (for a surface with no agent). Show it as a table; make_frames (or make_plan) makes the rows when the person says go (or at once when they asked to make them).

## preview_brand_style

The sample ad drawn with these style fields, nothing saved: for showing a change before it is kept.

## remix_ad

Make this ad's idea for the caller's own brand: Klayson's designer looks at the ad and draws its idea by hand the way the brand draws its own ads, with the caller's product, logo, colors and type, none of the other brand's logos, marks, words or numbers, and every line of copy written in the brand's voice from the brand document; every layer is editable. No template is filled in and no image model is used. Returns the new design with its render_url and the primary text and headline to publish it with (ad_copy), or, while it is still being drawn (a few minutes), status drawing and a job_id for get_job. Records a remix signal. Change it afterwards with the layer tools (get_frame_tree, then set_text, replace_text, update_styles or batch_edit).

## remix_picture

Remake an ad the person uploaded (a screenshot or saved image of another brand's ad) for their brand: Klayson reads the uploaded ad and its designer draws the same idea by hand the way the brand draws its own ads, with their product, words, colors and type, every layer editable. No template is filled in and no image model is used. Pass the picture's asset id (in the chat, the attachment's id). Same options as remix_ad. Returns the design with its render_url and the primary text and headline to publish it with, or, while it is still being drawn (a few minutes), status drawing and a job_id for get_job.

## replace_text

For any change the person asks to an ad Klayson made or showed in this conversation, even when they don't say Klayson. Find and replace words in an ad's texts, like a design tool's Find and replace: replacements = [{from, to}], every text (and words on a curve) holding from gets to instead, its styled ranges kept on their words. match_case false matches any case. node_ids limits it to some layers. design_ids (more ads) or canvas_id (every ad on a canvas) make the same change across ads, each ad its own save and undo step, and the answer lists each ad (changed, already so, or failed and why). Example: replace_text(design_id, design_ids=["dsg_b"], replacements=[{from: "20% off", to: "25% off"}]). Free, idempotent.

## research_ads

The research report before making ads: the top performing ads for a category and for named competitors, ranked by Klayson's score (how long an ad ran, versions kept, reach), each with its picture, angle, hook and why it works; the angles and hooks that score best. Static image ads only. Pass competitors as names, websites or Meta page ids (up to six; an account Klayson has not read is read from the Ad Library on the spot, and with a category given only their ads about it are kept). The category itself is asked of the Ad Library when Klayson has few ads for it. Shown as a card in Claude, 12 ads at a time.

## rewrite_copy

Change the words that run with an ad on Meta (its primary text, headline, description and button) without making a new picture. Pass any of them to set them exactly, or instruction ('shorter', 'lead with the price', 'more playful') to have the primary text and headline rewritten. Free. Read them with get_design (ad_copy) or get_canvas_items with words=true. The words drawn on the ad itself are its layers: get_frame_tree, then set_text, replace_text, update_styles or batch_edit.

## run_workflow

Run the workflow: every stale frame in order (research, then brief, then output), or with only=[frame ids] those frames plus anything stale before them. The brief is free. Returns the run and the job: poll get_run or get_job. A run already going for this workflow is returned instead of starting a second. Only when the person asked to run or make.

## save_brand_style

Save the brand's style: the fields given go onto the workspace's design system, which every designed ad, the Template canvases, the Brand frame and the picture engine read. confirm=true (the default) records that the person confirmed it, with who and when; only after the person said it looks right.

## save_to_library

Save something to the brand's library, as approved work or as a reference, so every agent sees it before making something for that medium. Save only after your person approves something you made, or shares something they like. Ask once ("Save this to Klayson as approved?") and save on a yes. Never save on your own reading of anyone's words. Give exactly one of: asset_id, a file uploaded through create_upload_link with kind library (a picture, a GIF, an MP4 or WebM video, or a Lottie JSON); url, a web page (Klayson takes a picture of it for its card) or a picture or video at an address; or code with code_lang (html, jsx, tsx or css: Klayson keeps the code and draws a picture of it). status is approved (the default) or reference (something they like that is not their own). medium is where it is used: web, app, ads, social, slides, email or print. title is a short name, note one line on why it is good. A picture that has to be made comes from a job: get_job with its id and wait true when you need it.

## scrape_brand

Scrape a website to (re)build the brand kit: colors, logo, about, voice. Replaces the scraped fields, keeps manual assets. Returns a job to poll with get_job.

## screenshot_frame

A quick picture of the frame as it is now (a JPEG at most 1024 px on its long side, about a thousand tokens), for looking at your own work after a whole section, with the lint's issues in words (the same lint as check_layout: errors first, then warnings). check_layout alone is cheaper when you only need the findings. Over MCP the picture rides along with the answer; over REST read the url. Not the export. Free. Waits for pictures still being made (up to about a minute), so one call is enough. node_id looks at one layer only, cut to the box it is drawn in, and scale 2 doubles the pixels, to check a headline's line breaks or a badge's edge closely: screenshot_frame(design_id, node_id="n7", scale=2).

## set_product_photo

Give one of the brand's products its photo: the asset id of a picture the person uploaded (in the chat, it is the attachment's id), or url, one of the photos read from that product's own page (its photos, as get_brand lists them). The photo goes on the product catalogue and into every creative made for that product.

## set_text

For any change the person asks to an ad Klayson made or showed in this conversation, even when they don't say Klayson. Change the words of text nodes: [{node_id, text}]. A newline in text breaks the line (a list item, a paragraph). The words keep their styled ranges where the same words are still there. To set the styled ranges too, give marks [{from, to, w (a weight, 700 bold), i, u (underline), s (strikethrough), sup (raised), color (#hex or var(--color-accent)), f (a font family), px (font size), ls (letter spacing, em)}] over text, or rich instead of text: the words with **bold**, *italic*, ~~struck~~ and ==accent== marked in them. Example: set_text(design_id, updates=[{node_id: "head", rich: "Calm energy, **no crash**."}]). style_text_range styles some words of a text without retyping it. get_node_info's paint.runs reads the ranges back. Free.

## update_frame

Change part of a frame: its data (a research query, the picked ads, a brief's prompt or n, an output's size or engine), its name, or where it sits. Data is merged key by key. A changed input marks the frame and everything after it stale.

## update_styles

For any change the person asks to an ad Klayson made or showed in this conversation, even when they don't say Klayson. Change styles on one or more nodes: [{node_ids: [...], styles: {padding: '32px', gap: '12px', color: 'var(--color-primary)'}}]. camelCase or kebab-case. A value of null or '' clears a property. Keys outside the whitelist come back as ignored. Each update may also carry, like Paper and Figma: rotate (degrees; the node turns about its centre after layout, so nothing else moves; 0 undoes it), absolute (true takes that ONE node out of its parent's auto layout, the rest keeps flowing; false puts it back at its place in the order with the styles it had) and constraints {horizontal: left | right | left_right | center, vertical: top | bottom | top_bottom | center} with optional fractions from 0 to 1: left, right, top, bottom (of the parent), center_x, center_y (where its centre sits in the parent), width (of the frame's width), height (of the frame's height). Pinned that way it holds when the frame goes from 4:5 to 9:16. Without the fractions Klayson measures where it is drawn now (or pass boxes from get_node_info). hidden (true hides the layer: it is not drawn on the canvas or in the export and the lint ignores it, the Layers keep it; false shows it again) and, on a picture, crop {x, y, scale}: the picture zoomed scale times inside its box (1 to 8) and panned to x, y (0 to 1, where 0.5 is centred), its fit kept, so a cutout stays whole until it is zoomed; crop null takes the crop off. Free.

## upload_asset

Upload one of the USER'S OWN images: the product that must appear in generated ads exactly as photographed (kind=product), a screenshot of their app or website for a software, app or service brand (kind=screen: shown in the product's place), their logo (kind=logo), or other brand imagery (kind=upload). NOT for other brands' ads whose style should be imitated: those are found with search_ads and remixed by id (remix_ad, or create_canvas with reference_ad_id). How to send it: check list_assets first (scrape_brand and the web app usually uploaded the product already), or pass url for an image already on the web. IMPORTANT: an image attached in the chat, or a file on the user's device, can NOT be sent through this tool — you do not have its bytes, and inventing data_base64 will fail. For those, call create_upload_link and give the user the link instead. data_base64 is only for API clients that genuinely hold the raw file. Several at once: files, a list of up to 10 {filename, data_base64 | url}, all of the same kind; the result lists the assets made and, per file, any that failed and why. kind=file takes a document instead of an image: a brand guide as a PDF, Word (.docx) or PowerPoint (.pptx) file up to 50 MB, or as url a Google Docs or Google Slides share link (fetched as its PDF; the document must be shared with anyone with the link), or a txt, md, csv or json file; its text is kept on the asset, and import_brand_guide reads a guide from its asset_id.

## write_html

Add to a frame by writing HTML with inline styles, the way you would write to a design canvas: flexbox (display, flex-direction, gap, padding, align-items, justify-content), real text in elements, <img> for pictures from the workspace's assets (upload_asset, the product's cutout), inline <svg> for shapes. layer-name="…" names a layer. A div (or a, button, span) holding only words with a box's own styles (a fill, a border, padding, a radius, a shadow) is a frame wrapping a text layer, so a button stays a box (its shadow a box shadow); a heading or a paragraph stays text. mode insert-children adds inside target_node_id (the root by default), on top of what is there unless before, after (a sibling's id) or index says where; replace swaps that node out. position:absolute with left, top, right or bottom (or inset) and a size places a layer exactly, in the frame or in a box with position:relative. Margins, grid, floats and outside pictures are dropped, and every drop is reported in notes with what to write instead. <x-dovey-clone node-id="n5" style="color: #fff" layer-name="CTA 2"></x-dovey-clone> inside the HTML is a deep copy of an existing layer (fresh ids, the styles given merged on top; design-id="…" copies from another ad of the workspace), like Paper's x-paper-clone: reuse a button or a badge while writing new structure around it instead of sending its HTML again. Write one visual group per call and look at the result with screenshot_frame; an ad you already have whole may go in one call. Free.
